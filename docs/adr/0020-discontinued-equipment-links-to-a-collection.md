# Discontinued equipment links to a collection

> **Supersedes the central decision of [ADR-0012](0012-discontinued-equipment-is-out-of-scope-for-profile-links.md)**, including its 2026-08-05 Humidifier addendum. ADR-0012's reasoning is left intact below the reversal because the objection it raised is real and is now accepted deliberately rather than answered.

A value that names equipment cpap.com no longer sells now resolves a **Collection Link** — a Profile Link whose target is a cpap.com collection page rather than a product page. ADR-0012 excluded exactly this and said so in terms: "a Profile Link to a category page is a poor thing on its own terms. It looks like a product link and is not one." Product has reversed that position, and the reason is link equity. Every migrated member holding a discontinued machine is a page that either links to cpap.com or links nowhere, and roughly 1,650 members held the four catch-all values alone in the April 2026 test migration. Silence on that many profiles is the more expensive option.

Worth recording so nobody re-derives it: PSD-311's written acceptance criteria said this all along — "Some legacy Value/Text entries may not have a clean cpap.com equivalent at all — map these to cpap.com/collections/cpap-machines or collections/cpap-masks". The plain-text answer came from a refinement comment on 2026-08-08 that flagged itself as unconfirmed, and ADR-0012 was written to it. That comment is retracted on the ticket. This ADR restores the acceptance criteria rather than overriding it.

ADR-0012's objection is accepted, not refuted, and the mitigation is the label. A **Mapping** is a `{value, url}` pair and the value is simultaneously the join key against what Discourse stores per member and the anchor text rendered by `profile-link-row.gts`. So the string is the only place a Collection Link can tell the truth about itself, and it does: the value is the equipment's name with `" (Discontinued)"` appended. ADR-0012 was right that the suffix renders verbatim in a user card. That is now the point — a link labelled `DreamStation Auto CPAP Machine (Discontinued)` is not pretending to be a product link, and a member reading their own profile learns something true. The rejected alternative was widening the Mapping to `{value, label, url}` so the label could differ from the join key. It was rejected because it buys a second string that can drift from the first, in a component whose entire premise is that one file feeds everything, and because the retreat it protects against — an ugly value — is better fixed by choosing a better value.

The base name is the **Sheet Export**'s `Suggested Title` when that names a real product, and the legacy `Text` column when it does not. `Suggested Title` is the curated name and is what ADR-0010 makes authoritative, but on the four legacy catch-all rows it is generic by construction — `CPAP Machines (Discontinued)` names no equipment at all. Those four titles are retired as values. A row that carried one now takes its own legacy name instead, so a member sees the machine they actually owned rather than a category they were bucketed into. This is a deliberate and narrow exception to ADR-0010, and it is the only one: for every row whose `Suggested Title` names a product, that title still wins.

Five of the seven exclusion reasons earn a Collection Link: `discontinued-suffix`, `not-active`, `unpublished`, `discontinued-tag`, and `no-matching-product`. Two do not. `blank-title` has nothing to name. `ambiguous-title-match` means the title matched more than one product, which is evidence the product is *still sold* and the sheet is wrong — linking it to a collection would hide a fixable data fault behind a plausible link, so it stays in the review doc until a human disambiguates it. Those rows, and any row a human deliberately leaves unlinked, remain **Unmatched Values**. The rejected alternative was writing them as plain text into the `Additional comments` field, which exists and is mapped; it was rejected because it makes the migration edit member-authored content to compensate for a missing link, which is irreversible in a way a missing Mapping is not.

Which collection a given piece of dead equipment belongs to is an editorial judgement and is hand-curated. Whether that collection exists is a fact, and ADR-0009 already says Shopify owns it. Both halves apply: the assignment comes from a reviewed table, and the collection is verified against Shopify on refresh. The targets are therapy-type collections — nasal masks, full face masks, APAP, BiPAP, travel — rather than model-specific ones. Model-level granularity was rejected for now because a link carries equity either way, because it would have required roughly a hundred editorial calls including fourteen nobody could make from the sheet alone, and because on a standing mechanism it is an unbounded curation burden. Coarse assignment is the substrate a later refinement would sharpen, not an obstacle to it.

This is a standing mechanism, not a migration step. ADR-0012's design frame was "a new user selecting a product cpap.com currently sells", and the exclusion it justified was permanent policy. Its reversal is permanent in the same way. A product that is active today and discontinued in six months is currently dropped into `ExcludedProduct` on the next **Catalogue Refresh** and its members' Profile Links silently disappear; under this decision it becomes a Collection Link instead. The one-time reading of this ticket was the more expensive one, because it has to be redone the first time a product retires.

## Humidifier returns to scope

ADR-0012's addendum put humidifiers out of scope entirely, on the grounds that "there is no Humidifier list to ship, at any quality bar." That was sound when the only outcomes were a product link or nothing: the tab has no `Suggested Title` or `Suggested URL` columns, all five legacy rows are discontinued devices, and two point at a search results page. It stops being sound the moment a Collection Link is available, because all five of those values are precisely what a Collection Link is for. `CPAP Heated Humidifiers` exists at `/collections/cpap-heated-humidifiers` and carries 27 products, so all five map to a real page.

The field stays a **text** field, and that is not a compromise. ADR-0012 changed it from `dropdown` to `text` as a retreat, and ADR-0015 had already established that a dropdown cannot be emptied. A Collection Link has no **Dropdown Option** by design (see ADR-0021), so a field that offers no options is the ideal shape for one — there is nothing to write, nothing to replace, and none of the destructive apply behaviour ADR-0011 guards against. `Humidifier` therefore stops being a Managed Field with no Mappings and becomes a Managed Field whose Mappings are all Collection Links.

Two loose ends inherited rather than created here. Gerhard Schlager reports that phpBB's `user_humidifier` is an option list rather than free text, which does not change anything above — the importer writes a string and the Mapping matches it — but it does mean the five legacy values are the complete set. And Humidifier came through empty for every member in the April run, a bug on the Discourse side that was still under investigation as of 2026-08-31. A correct Mapping cannot resolve a value that was never written.

> **"Humidifier returns to scope" reversed by [ADR-0022](0022-humidifier-is-dropped-not-deferred.md) (2026-09-02).** On manual verification, none of the five legacy values actually resolved to `CPAP Heated Humidifiers` or any humidifier-specific page — all five linked to the cpap.com homepage, which carries no link equity, so the premise above did not hold in practice. Product separately confirmed Humidifier does not need to be carried through this migration at all. Everything else in this ADR — the Collection Link mechanism itself, and its use for discontinued Machine and Mask values — is unaffected.
