# Shopify is the authority for product URLs, not a rewritten sheet URL

The source spreadsheet was built for a migration to sleeping.com, so every `Suggested URL` in it points at that domain. The plan of record was to rewrite `https://sleeping.com` and `https://www.sleeping.com` to `https://www.cpap.com`, then check each result over HTTP and, on a 404, fall back to the row's `URL` column. Both halves of that plan failed on contact with the data, and the replacement is worth recording because the rewrite looks so obviously sufficient.

The fallback resolves nothing. All seventeen Machine rows carry a sleeping.com value in `URL` — a link to the site being migrated away from. Of the twelve confirmed Mask failures, six carry the identical path minus the `www.` prefix, so the fallback 404s exactly as the primary did. Across fifteen known failures the specified fallback corrected zero.

HTTP status is also not a diagnosis. `AirCurve 11 ASV` returns 404 while being `ACTIVE` in Shopify with seven units in stock at $3,299, because it was never published to the Online Store sales channel; its slug was always correct. `Morf Nasal Mask` returns the same 404 because it is `ARCHIVED` and tagged `Discontinued`. Treating both as "bad URL, find a better slug" would have produced a confident wrong answer for the first, since there is no better slug to find.

The Shopify Admin API distinguishes them, and it also removes the guess. Looking a product up by the handle taken from the sheet's `Suggested URL` returns its status, its publication state, its tags, and `onlineStoreUrl` — which is already the canonical `https://www.cpap.com/products/…`, not the `myshopify.com` domain. So a Mapping's `url` is read from Shopify rather than constructed by string surgery, and a product is admitted only when it is `ACTIVE`, has a non-null `onlineStoreUrl`, and is not tagged `Discontinued` (ADR-0012). Every exclusion is reported with the reason Shopify gave for it, so the residue is a list of merchandising facts someone can act on rather than a list of status codes.

A throttled HTTP pass still runs over the final list, because Shopify cannot see theme routing, redirects, or storefront-level oddities, and the whole point is that the rendered Profile Link resolves. It confirms; it does not decide. cpap.com rate-limits aggressively — eight concurrent requests produced 429 on sixty-eight of eighty-six URLs, and 429 is recorded as its own unresolved outcome rather than being folded into pass or fail. That is also why verification is a deliberate command and never part of a build or a pre-commit hook.
